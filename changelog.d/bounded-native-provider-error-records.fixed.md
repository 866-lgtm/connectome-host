- llm-calls records from the Anthropic and Bedrock paths bound a failed call's error text as the generic logging wrapper's records do, so a provider error that echoes the whole rejected request no longer writes it into the record a second time beside the raw request. The `error` object keeps its shape (`name`, `message`, and on the Anthropic path `stack`, which no longer repeats the message); `errorChars` gives the whole message's length when it was cut, and the provider's classification (`errorType`, `httpStatus`, `providerErrorCode`, `retryable`) sits beside it. Reading a hostile error no longer throws, so the provider's error is always what the caller gets.

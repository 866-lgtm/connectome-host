- llm-calls records from the Anthropic and Bedrock paths bound a failed call's error text as the generic logging wrapper's records do, so a provider error that echoes the whole rejected request no longer writes it into the record a second time beside the raw request. The `error` object keeps its shape (`name`, `message`, and on the Anthropic path `stack`, which no longer repeats the message); `errorChars` gives the whole message's length when it was cut, and the provider's classification (`errorType`, `httpStatus`, `providerErrorCode`, `retryable`) sits beside it. Nothing in a failed call's logging on these paths can replace the provider's error any longer: neither reading a hostile error nor summarizing the request.

- llm-calls records from the Anthropic and Bedrock paths bound a failed call's error text as the generic logging wrapper's records do, so a provider error that echoes the whole rejected request no longer writes it into the record a second time beside the raw request. The `error` object keeps its shape: `name`, cut at 128 characters; `message`, cut at 4,000 to its head and tail around a marker stating the omission; and on the Anthropic path `stack`, whose header names the message above instead of repeating it when that header is the error's own "Name: message" line, and which is cut at 4,000 as well. `errorChars` gives the whole message's length when it was cut. For an `Error` carrying them, the provider's classification (`errorType`, `httpStatus`, `providerErrorCode`, `retryable`) sits beside it. On the Anthropic path the call ledger's ERROR cause, live and restored after a restart, reads this same bounded message.
- Logging on these two paths no longer changes what a call returns or throws. It runs after the provider call, outside its try, and neither reading a hostile error nor summarizing the request can throw into it. A call whose request or response can't be summarized gets a minimal record (`summaryUnavailable: true`) with its kind and timing, and for a failure its bounded error, so no call goes unrecorded. A rejection with `undefined` is recorded, and reported to the credential monitor and the call ledger, as the failure it is.

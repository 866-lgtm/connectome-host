- `mcpl_restart` keeps its overlay note when the restart throws, and an `mcpl-servers.agent.json` that can't be read no longer turns a successful restart into "mcpl_restart failed": the receipt reports the restart, says the file couldn't be read or parsed and that the next host start will stop on it until it's fixed, and doesn't quote it. When the live server's overlay entry is malformed, the restart's note says so and that the next start skips it. The overlay-replacement receipts no longer report `AGENT_TIMEZONE`, which the host sets over every server's mapping, as lacking, and they do report a replacement that names a different `access` grant as lacking the operator's, comparing each grant as it's dialled.
- `mcpl-servers.agent.json` entries are read the same way by the boot, the startup warnings, `mcpl_list`, `mcpl_restart` and `mcpl_unload`. A shape that loaded before loads the same way, and the startup log says how it was read: `null` in a field reads as the field absent; a `transport` other than `stdio` or `websocket` reads as absent, as agent-framework reads it; an `env` value that isn't text, a number or true/false passes on as its text, as before, and an empty list as `env` reads as no env; a number `toolPrefix` reads as its text; and a tool or feature-set list given as one name reads as a list of one, which used to be read character by character, so a one-name deny list denied nothing. A number or true/false in `args` or `env` reads as its text, so an entry an earlier `mcpl_deploy` saved with `{ "PORT": 3101 }` still loads. A number past 2^53 has already lost precision when the file is parsed, so write such a value as a string.
- `disabled: true` tombstones a server whatever else its entry holds; the agent's unload wins. An entry that isn't an object, or has a `disabled` that isn't true or false, a `command`, `url`, `token` or `access` that isn't text, `args` that aren't a list of text, numbers or true/false, an `env` that isn't a map, or a name list that isn't a list of names, is skipped by the boot, which logs why, and the operator's definition loads. So is one for which agent-framework would open nothing: `transport: "websocket"` without a `url`, `transport: "stdio"` without a `command`, or neither a `command` nor a `url`. Two of these used to stop the host from starting: a `null` entry, and `args` that aren't a list. `mcpl_list` names a skipped entry as malformed, and no receipt counts it as replacing anything. `mcpl_unload` of a server whose entry is malformed tombstones the operator's server the boot loaded in its place.
- `mcpl_deploy` holds a new entry to the plain shapes, saving nothing for an `env` value that isn't text, a number or true/false, a `transport` other than `stdio` or `websocket`, or a `toolPrefix` that isn't text, where a `null` env value used to be saved before the deploy threw. An empty list as `env`, which strict function calling sends for "unspecified", deploys with no env.
- A file that isn't valid JSON, whose root isn't an object, or whose `mcplServers` isn't a map of entries, still stops the start, now with an error naming the file and advising a fix: moving it aside would load every server the agent unloaded. `"mcplServers": null` reads as no entries, as before, and a root with other keys but no `mcplServers` is named in the startup log, since a misspelled key would drop the agent's tombstones. The file is now written through a temporary file and renamed, so a crash mid-write can't leave it truncated. `mcpl_unload` reads the file again after its disconnect, so an entry another call wrote meanwhile isn't lost, and an inherited name such as `constructor` is no longer taken for an entry.
- A replacement whose `access` names a host variable is named, as one whose `token` does. `mcpl_restart`'s note says that it describes the file as it is now, since the restart reconnects with the last connect's configuration: a hand edit takes effect at the next host start, unless a later `mcpl_deploy` replaces it. A hand-edited `access` grant name is read trimmed, as `mcpl_deploy` writes it, so the host asks for the grant the receipts compare. An entry is read by the connection agent-framework opens for it, which an explicit `transport` decides: its reconnect default, the receipts and `mcpl_list`'s label all follow that connection, so a spawned entry that also names a `url` is no longer respawned on exit by a reconnect meant for a dialled one.

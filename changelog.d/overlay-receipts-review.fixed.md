- `mcpl_restart` keeps its overlay note when the restart throws, and an `mcpl-servers.agent.json` that can't be read no longer turns a successful restart into "mcpl_restart failed": the receipt reports the restart, says the file couldn't be read as an overlay and that the next host start will stop on it until it's fixed, and doesn't quote it. When the live server's overlay entry is one the boot skips, the restart's note says so and what the next start loads, and for a tombstoned id it says the overlay keeps the server unloaded and how to restore it. The overlay-replacement receipts no longer report `AGENT_TIMEZONE`, which the host sets over every server's mapping, as lacking, and they do report a replacement that names a different `access` grant as lacking the operator's, comparing each grant as it's dialled, as written.
- `mcpl-servers.agent.json` entries are read the same way by the boot, the startup warnings, `mcpl_list`, `mcpl_restart` and `mcpl_unload`. The boot passes each entry to agent-framework as it did before, so a file that worked keeps working the same way, and the startup log names each place it reads an entry differently: `args` holding numbers or true/false read as their text, where the start used to stop; a tool, feature-set or capability list given as one name reads as a list of one, where it used to be read character by character, so a one-name deny list denied nothing, or ignored; a number or true/false `toolPrefix` reads as its text, so calls to the server's tools reach it; and a `transport` other than `stdio` or `websocket`, which agent-framework ignores, is named.
- `disabled: true` tombstones a server whatever else its entry holds; the agent's unload wins. The boot skips an entry that isn't an object, has `args` that aren't a list of text, numbers or true/false, names neither a `command` nor a `url`, or has a `disabled` that's truthy but not `true`. It logs why, and loads the operator's definition, if any. Two of these used to stop the host from starting: a `null` entry, and `args` that aren't a list of text. `mcpl_list` names a skipped entry as malformed, and no receipt counts it as replacing anything. For an id the operator defines, the advice says that `mcpl_unload` tombstones the operator's server, which the boot loaded in the entry's place.
- `mcpl_deploy` holds a new entry to the plain shapes, saving nothing for an `env` that isn't a map of text, numbers or true/false, a `transport` other than `stdio` or `websocket`, or a field of another wrong kind, where a `null` env value used to be saved before the deploy threw. An empty list as `env`, which strict function calling sends for "unspecified", deploys with no env.
- A file that isn't valid JSON, or whose root is `null`, still stops the start, now with an error naming the file and advising a fix: moving it aside would load every server the agent unloaded. Every other file starts the host as before. A root that isn't an object, or an `mcplServers` that's text, a number or true/false, holds no entries, and an `mcplServers` that's a list holds its items as entries named by position; the startup log names each. It also names keys besides `mcplServers`, since a misspelled key would drop the agent's tombstones. `mcpl_unload` reads the file again after its disconnect, so an entry another call wrote meanwhile for another id isn't lost, and an inherited name such as `constructor` is no longer taken for an entry.
- A replacement whose `access` names a host variable is named, as one whose `token` does. `mcpl_restart`'s note says that it describes the file as it is now, since the restart reconnects with the configuration of the server's last connect: a hand edit made since then takes effect at the next host start, unless a later `mcpl_deploy` replaces it. The receipts read an entry by the connection agent-framework opens for it, which an explicit `transport` decides. `mcpl_list`'s source label reads the overlay file as it is now, and its target label is a server's command, else its url, as before, since agent-framework's status doesn't say which of the two it opened.

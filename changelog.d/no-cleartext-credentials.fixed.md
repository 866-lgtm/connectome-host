- `mcpl_deploy` refuses a server that would send a credential over unencrypted `ws://` to a host other than this machine, where anyone on the network between could read it. It recognizes four carriers: the `token` field, the credential an `access` grant attaches, a user or password in the url, and the url's `token` parameter, the one agent-framework's transport sends. No other query parameter is recognized. The refusal says to use `wss://`, or, if that network is private, to ask the operator to add the server to the recipe, and it says when a server already running under that id is left as it was. A recipe server like that, or an overlay entry deployed before this change, still loads, with a warning at startup; there a grant counts only when the recipe's identity attaches its credential. This machine is `localhost`, 127.0.0.0/8, `::1`, IPv4-mapped 127.0.0.0/8 addresses, and `0.0.0.0` and `::`. The tool's `url`, `token` and `access` descriptions say what it takes over `ws://`.

- The web UI's `/files/<mount>/<path>` route and the activity module's origin hint read workspace files through agent-framework's `readFileFromDisk`, which keeps the mount's `followSymlinks` policy (off unless the mount sets it) and reads a file only if its canonical path lies inside the mount. Before, both resolved the path by its text and read it with Node's file calls, which follow any link: a link inside a mount let the files route serve a file from outside the mount to whoever could open it, and let the activity module read the first 2 KiB of such a file for a routing hint. The files route now answers 403 for a link the mount refuses, one leading outside it, or a path no mount holds, and 404 for anything else the read can't give. The activity module skips such a file.

- Anthropic cache-keepalive sends now appear in `llm-calls` logs and the live/reloaded spend ledger as `keepalive` calls, including ineffective cache writes and errors. Rows preserve terminal vendor usage, split cache-write buckets, and pricing metadata. Existing keepalive callbacks remain composed and isolated; replay payloads are unchanged. Requires a membrane release containing antra-tess/membrane#87. One row represents one logical keepalive send, including any SDK-internal retries, rather than one row per HTTP attempt. A failed send's error is bounded and classified as a complete or stream call's is, as far as the error carries a classification. `/bug` counts these sends among its provider calls and lists a failed one's kind as `keepalive`. The Health call table shows these rows as `keepalive`, in a muted tone of their own.
- A failed or refused keepalive send's row names the request it replayed (`keepalive.request`, a hash of the request's bytes), and keeps the request itself unless it is the one this process last kept for that lineage. membrane replays the same request until a real call replaces it, so a lineage that keeps failing or being refused writes its whole request once rather than in every row. A request counts as kept once its row's append succeeds. The process remembers sixteen lineages, the one used longest ago forgotten first, and a forgotten lineage's request is kept again. With `LLM_CALLS_FULL_PAYLOADS=1`, every row keeps its request.
- The credential monitor now hears keepalive sends as it hears turns: a send the provider rejects for its credential raises the auth alert while the resident is idle, rather than at its next turn (membrane keeps poking an idle lineage for a day after its last real request by default), and a send that succeeds settles an auth alert as a successful turn does.
- A refused keepalive send raises the off-path refusal alert (`refusal-offpath`, as a refused compression call does), since the context it replays is what the resident's next turn would send. It alerts unless the refused request is the one this process last alerted for that lineage: another alert about the same bytes would ask nothing new of the operator, and a real call reseeds the lineage, usually with other bytes. A send can replay a turn the provider already refused; its refusal, tested again while the resident is idle, is alerted once as off-path. agent-framework throttles the alert's webhook per agent and kind; `failures.log` and the ops trace get every alert. The alert's data now puts the refused call's kind under `call`, so `failures.log` keeps `refusal-offpath` as the record's kind, and its size is the whole prompt, cache reads and writes included, for a refused compression call too.
- `connectome-doctor`'s inference stage skips keepalive rows, so it reports the last real model call and its time rather than the last poke. It also shows the newest refused and the newest failed poke since the agent's last turn, and warns on a refused one. It splits the log at newlines only, so a row holding U+2028 or U+2029 is no longer lost (the diagnostics dump's read too); it counts newer rows it couldn't read, says when the last row is incomplete, and doesn't claim no inference followed an ingest older than its window.

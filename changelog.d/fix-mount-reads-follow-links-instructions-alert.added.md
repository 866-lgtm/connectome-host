- An `instructions-unavailable` ops alert whenever the instructions module injects nothing: no workspace, an unknown mount, a missing or unreadable file, a file that is itself a link or that lies outside its mount, or a read that hasn't finished in 1.5 s. It says why, and what to do where the reason alone doesn't. It reaches the TUI, the web UI's alert strip, `failures.log`, the ops webhook and, at the `status` tier, the notices module's status channels. `instructions-unavailable-clear` stands it down once the file loads again, after a session switch too. Each reason is raised once until then, under the name of the agent the host runs. Before, an agent running without its instructions showed only as a log line. One read is in flight at a time: a read that never finishes, such as one waiting on a FIFO at the path, leaves agents without their instructions until it finishes, the session is switched or the host restarts, and no other read starts meanwhile, where before each turn started one.
